# Сборка дистрибутива «Канцлер Про» (BACKLOG D-3)

Проект — десктоп-приложение на Flet + SQLite. Ниже два способа получить
переносимый исполняемый файл; оба собирают приложение из исходников этой
ветки и **не** включают базу данных (она создаётся при первом запуске в
каталоге `data/` рядом с исполняемым файлом либо по переменной `KANZLER_DB`).

## Способ 1 — `flet build` (рекомендуемый)

Требуется Python 3.12+, Flutter SDK (для desktop-таргетов) и пакет `flet`.

```bash
pip install -r requirements.txt flet-cli

# Из корня проекта:
flet build exe             # Windows: build\windows\exe\...  → KanzlerPro.exe
flet build bundle -t linux # Linux AppImage/deb (при наличии тулчейна)
```

Параметры:

* точка входа — `main.py` (определяется автоматически, можно задать явно:
  `flet build exe --target main.py`);
* для «одного файла» добавьте `--onefile` (медленнее стартует, но удобнее
  разносить);
* иконка/метаданные — `flet.yaml` (создаётся командой `flet create`, при
  желании скопируйте секцию `meta:`).

## Способ 2 — PyInstaller

Если Flutter SDK недоступен (например, закрытый контур без интернета),
можно упаковать интерпретатор целиком:

```bash
pip install pyinstaller
pyinstaller kanzler.spec   # готовый spec в корне репозитория
# результат: dist/kanzler_pro/kanzler_pro(.exe)
```

## Инструкция выпуска версии

1. Обновите `CHANGELOG.md`: перенесите нужные пункты из `[Unreleased]` в
   новый заголовок вида `## [1.x.y] - YYYY-MM-DD` и добавьте ссылку-дифф.
2. Прогоните проверки: `python -m ruff check app main.py tests`,
   `python -m pytest -q`, `python -m app.doctor`.
3. Сделайте коммит релиза и тег: `git tag v1.x.y && git push --tags`.
4. Соберите exe (см. выше), архивируйте каталог `dist/…`, приложите
   `.env.example` и краткую памятку оператору.
5. Загрузите архив к тегу как artifact релиза.

Перед раздачей: резервные копии пользователей лежат в `data/backups/`
(A-4) — первый запуск новой версии на рабочей машине автоматически делает
копию текущей базы.
